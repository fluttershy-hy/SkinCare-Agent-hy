# 渐进咨询和混合检索

聊天中出现泛红、刺痛等症状时，`SkinConsultation` 以用户 ID 和会话 ID 为键在内存中保存症状和本轮明确提供的线索，部位未知时先问部位，再问近期变化；已有确认肤质时直接使用，否则才询问肤质；已在问题中提到的刺痛等伴随感受不重复问；这些内容不会自动变成持久过敏史。收集后检索并回答，提供观察记录选项。出现呼吸困难等紧急描述会跳过追问。重启或新建会话会开始新的收集。

检索时先用领域词典扩展查询，分别运行中文二字词 BM25 和 BGE 向量召回，以 RRF 融合排名，再对候选重排。已配置 BGE 交叉编码器时，把它的原始 logit 通过 sigmoid 映射为 0～1 的相对分数，并以 0.10 为当前阈值；低于阈值的片段不会交给聊天模型。阈值是本项目的初始参数，应该用更多样例校准，不能理解为医学准确率。没有配置交叉编码器时回退到本地 BGE 向量相似度重排，阈值 0.75。配置不完整或文件不存在时启动报错，避免误以为交叉编码器已经启用。

## Windows 配置本地重排模型

需要联网下载一次约 283 MiB 的 ONNX 模型和 tokenizer，不需要新 API 密钥。`data/reranker` 不进入 Git。项目根目录的 PowerShell 中执行：

```powershell
. .\scripts\setup-reranker.ps1
mvn spring-boot:run
```

第一行最前面有一个点和空格：它让两个环境变量保留在当前 PowerShell 窗口。新开窗口后再次执行第一行；文件已存在且校验通过时不会重新下载。模型下载来源为 Hugging Face 的 `Xenova/bge-reranker-base`，脚本使用 SHA-256 检查文件。聊天模型仍使用原来的 `SKINCARE_LLM_API_KEY`，重排模型不使用该密钥。

只有代码随 GitHub 拉取：书籍 OCR 文字和向量需要按 [书籍导入记录](book-knowledge-import.md) 在本机准备。未配置重排模型时仍可使用本地向量重排，检索结果的 `model` 字段显示当前实际使用的模型。
