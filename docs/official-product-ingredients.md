# 产品网页候选成分提取（2026-11-09）

普通聊天入口只需填写具体产品名。已由项目维护者核对的商品放在服务端 `OfficialProductCatalog`，包含官网 URL、市场和 SKU；用户不需要自己配置品牌域名或查 SKU。目前目录只收录 `CeraVe Moisturizing Cream` 的美国官网版本。查不到的商品会明确说明来源不足，用户可选择粘贴手中包装成分表。SKU 是商品识别线索，不等于配方修订版本；最终仍需对照包装。

高级核对入口仍保留两种方式：用户提供具体产品全名、销售市场、页面明示的 SKU／型号／版本标识，系统可以据此核对尚未收录的商品；这不是普通用户使用已有目录的必填步骤。

1. 在聊天框只填产品名：若命中服务端目录，直接读取已核对的官网页面。未命中时，若服务端已配置 `SKINCARE_SEARCH_API_KEY`，`ProductSearchService` 寻找名称匹配的 HTTPS 页面，页面明确标注全成分时提取候选列表。市场和 SKU 可选；未填写就不声称核实过这两项。搜索摘要不参与成分提取。
2. 在页面填写产品名与具体产品网页 URL，点击“从网页提取候选成分”：调用 `POST /api/products/web-ingredients`，成功后把成分载入原聊天窗口的成分框，并显示来源链接。

示例环境设置（PowerShell）：

```powershell
$env:SKINCARE_SEARCH_API_KEY="你自己的 Tavily 密钥" # 仅按产品名自动寻找官网时需要
mvn spring-boot:run
```

不再要求配置品牌域名。服务仅请求公开 HTTPS 页面、默认 443 端口，拒绝本地与内网地址、含用户信息的 URL 和跳转。响应必须是 HTML，标题包含产品名，页面有明确的“全成分 / 完整成分表 / Full Ingredients / Complete Ingredient List”区域或 `data-full-ingredients`。市场与 SKU 如提供则额外核对；未提供时保持未知。提取 5～150 项、总长不超过 6000 字符后返回页面链接与查阅日期。页面无法访问或缺少全成分区域时不补全。网页是否属于品牌官方不再自动判断。

这是一种**受约束的官网页面提取**，并不等于全网所有产品、所有官网模板都可自动读取。2026-11-09 环境已允许 CeraVe、Vanicream、理肤泉官网和 Tavily 域名。实际 HTTP 测试：三款官网产品页均返回 200；Tavily 在未带密钥的连通测试中返回 401，说明域名可达但不能据此证明有可用搜索密钥。应用端到端请求 `www.cerave.com/skincare/moisturizers/moisturizing-cream`，输入官网标题 `Moisturizing Cream`、市场 `US`、页面 SKU `3606000537729`，返回 24 项、来源 URL 和当日查阅日期。首项为 `AQUA / WATER / EAU`，末项为 `ETHYLHEXYLGLYCERIN`；没有把官网全文复制进仓库。Vanicream 和理肤泉页面仅验证了可访问与页面上存在成分区，尚未完成与包装版本一致的端到端提取。

官网自己提示成分表会更新，务必以手中包装为准。SKU 不证明配方修订版本，因此上述结果只代表**2026-11-09 该美国官网页面展示的列表**，不能当作中国大陆在售包装的成分。目录外商品的自动网页搜索仍需要服务端配置 Tavily 密钥；普通用户不应自行配置。虚构 HTML 测试覆盖错产品、可选标识不符、摘要不完整和本地地址；仿冒域名不再被当作已核实官网。

2026-11-09 的目录外端到端验证：在已配置服务端 Tavily 密钥的环境中，只输入 `Vanicream Moisturizing Cream`，搜索返回该产品页面，提取器读取页面独立的 `Ingredients` 区域；聊天响应为 HTTP 200、`PRODUCT_SEARCH`，附原网页 URL 和“网页候选（来源未核实）”标记。这个验证说明不必逐品牌配置域名，也不证明所提取列表与用户手中包装完全一致。

成功返回的是“网页明确标注的候选全成分”，使用时仍应与手中包装的地区、批次和标签核对。它不会自动保存成用户确认的包装成分表，也不能凭列表判断个人过敏原因、准确浓度或实际功效。页面不可访问或信息不够时，系统继续显示网页候选和资料不足提示，不从搜索摘要补全成分。
