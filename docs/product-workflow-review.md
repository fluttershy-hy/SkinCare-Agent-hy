# 产品解读工作流与资料核查（2026-11-01）

用户提供的 `SkinCare-Knowledge.doc` 是需求草稿和候选资料清单，不是已核实的成分或医学来源。本次先把可由现有代码可靠实现的流程落地：在同一聊天窗口填写具体产品全名、可选的完整成分表、使用部位、当前状态、自述敏感和已确认过敏成分。若只有产品名，调用现有 `ProductSearchService` 寻找配置过的品牌官网候选页；该服务不会提取完整 INCI，所以此时不评价适用性。用户粘贴成分表后，Java 保留原顺序并强制匹配已确认过敏成分，再检索来源并生成谨慎回答。未确认的“脂皮”或敏感描述不写入长期画像，也不等同诊断。

以下主张尚无可核对的原始资料、授权数据或确切产品配方，**没有进入确定性风险规则**：

- “适乐肤神经酰胺屏障修护润肤霜”与英文 `CeraVe Moisturizing Cream` 是同一具体版本，以及文档列出的完整 INCI。产品各市场或版本可能不同，需要包装全名、地区、批次或官方完整列表。
- 将 C11–C24 油脂或所有脂肪醇统一标为脂溢性皮炎高风险，进而断言面部不可用、身体适合用；以及“厚重霜体给马拉色菌提供温床”的个体结论。这些需要具体成分、配方和针对人群的证据，不能从名称或质地一跳推到个人结论。
- 用单成分致痘 0–5 分直接给整款产品或个人标注五级风险；“已确认过敏原匹配”与“法规禁限用”也不能合并成同一过滤规则。前者是个人已确认记录匹配，后者需要地区、用途、浓度和现行法规。
- 文档中列出的 Open Cosmetics MCP、INCI API、Dermalytics、CureSkin、INCILABS 等数据量、价格、许可、接口能力及质量。接入前需核对官方地址、API 文档、许可条款、样例响应与真实产品覆盖。

若要进一步实现自动 INCI 查询与病理风险标签，最有用的补充是：① 一款演示产品包装上的完整名称、销售地区和完整成分表，最好附品牌官网具体产品页；② 拟接入数据源的官方项目/API 文档和许可链接；③ 脂溢性皮炎及马拉色菌相关**原始研究或专业指南**中支持具体成分判断的章节。项目仅使用虚构用户，不需要真实病历。

## Open Cosmetics 源码核对（2026-11-01）

用户提供了 [AndyZhuang/opencosmetics](https://github.com/AndyZhuang/opencosmetics)。核对其 `master` 分支提交 `e3d879c` 的 README、`docs/API.md`、`mcp-server/README.md`、`data/reference_formulas.json` 和 `LICENSE` 后，结论是：

- 它确实提供按中文名/INCI 查**原料**的 `/api/ingredients/search`，MCP 的 `ingredient_query` 也是原料监管查询；另有配方分析与规则接口。这些接口可作为未来的原料名称和来源交叉查询候选。
- MCP 的五个工具没有“按任意中文商品全名查询官方完整产品 INCI”的工具。仓库有 20 个手工整理的参考配方，其中包括 `CeraVe Moisturizing Cream`，但该 JSON 仅称数据来自公开披露与配方分析，未逐条附官方产品页、销售地区及版本；不能因此把它当作当前适乐肤产品的已核实配方。
- `LICENSE` 对原创代码采用 MIT，同时明确 DuckDB 汇编数据涉及 EU Annex 的 ODbL 和 BEBD 等上游条款；仓库 README 的“数据 CC-BY 4.0”不能覆盖全部上游许可。没有把该 DuckDB 或参考配方复制进本项目。
- README 的 65 条规则面向配方师的法规、成本、pH 等审查，并非已验证的脂溢性皮炎个人适用性模型。因此尚未把返回的 `PASS/REJECT` 映射为“用户可以用/不能用”。

下一步若要自动查产品完整 INCI，仍需要**能按具体商品版本返回成分表且允许程序调用的产品级来源**，或先提供一款演示商品的品牌官网成分页。Open Cosmetics 可另作原料级查询候选，但不代替产品级来源。

## 当前实际落地状态（2026-11-01）

- 同一聊天窗口可填具体产品名、完整成分表、使用部位、当前状态、自述敏感及本次已确认过敏成分。用户勾选“完整包装成分表”后，按用户 ID 将该产品文本保存到 H2；下次问同名产品先查本地，再使用已有 Tavily 官网候选页查询。不同用户隔离，记录标记为“用户确认的包装成分表”，不是品牌官方版本。产品名自然语言识别仍是有限规则。
- Java 先分割并标准化小型名称表、匹配已确认过敏成分；命中时不给模型机会输出相反建议。无命中仅返回 `UNKNOWN`，不宣称“安全”或“五级风险分”。香精和游离棕榈酸的研究线索分别标注 AAD 人群范围及 Europe PMC 体外条件；法规状态在缺少版本、用途和浓度时明确为未核实。
- 真实模型调用已经通过云环境代理修复并完成虚构输入端到端验证。模型只负责对已检索资料作自然语言解释；Java 只附加回答实际引用的已命中来源。
- **尚未实现**任意中文产品的官方完整 INCI 自动抓取、NMPA/欧盟法规实时逐项核验、CureSkin/INCILABS/商业 API 数据导入、马拉色菌个人高风险规则或 GREAT/GOOD/MODERATE/HIGH RISK 五级适用评级。所列候选数据源的许可、版本和有效性仍需逐个验证，不能假装已经接入。

## 继续完善（2026-11-02）

补上已保存包装成分表的查看、载入两款进行比较、删除流程，仍在同一聊天窗口操作。`GET /api/products/saved/{userId}` 只返回该 ID 的记录，`DELETE` 也只删除该 ID 指定产品；测试覆盖跨用户读取与删除隔离。该演示应用没有登录认证，用户 ID 不是身份凭证，因此不适合存放真实个人资料。此项不改变“用户自述包装成分表”与“官方配方”的来源区别。

同日又加入[受约束的品牌官网页面提取](official-product-ingredients.md)：在配置官网精确域名后，要求页面同时可核对具体产品全名、市场、版本，并明确标注全成分；否则不导入。它缩小了“只能给官网候选页”的缺口，但不等于任意产品通用查询，也没有通过当前云代理实际读取成功的品牌官网配方。此前列出的 NMPA/欧盟实时核验、商业产品库和马拉色菌个人高风险评级仍未实现。
